# AGENTS.md

Repo-specific guidance for OpenCode sessions working in `minicountant`.

## What this is

A local-first, offline-first personal finance PWA. Nuxt 4 + `@nuxt/ui` v4 + Dexie (IndexedDB) + VeeValidate/Zod + `@vite-pwa/nuxt`. IDR only (MVP). Single user, single company.

`ssr: false` is intentional — everything runs client-side against IndexedDB.

## Commands

Use pnpm (declared via `packageManager`).

- `pnpm dev` — Nuxt dev server on `http://localhost:3000`. PWA enabled in dev (`pwa.devOptions.enabled: true`).
- `pnpm build` — production build.
- `pnpm generate` — static build (sets `NUXT_PUBLIC_SITE_URL` for OG image).
- `pnpm preview` — preview built app.
- `pnpm lint` — ESLint via `.nuxt/eslint.config.mjs` (regenerated by `nuxt prepare`).
- `pnpm typecheck` — `nuxt typecheck` (vue-tsc under the hood).
- `pnpm postinstall` runs `nuxt prepare` — do not skip; lint needs `.nuxt/eslint.config.mjs`.

**No `test` script yet.** Phase 1 of `/plan/TODO.md` adds Vitest. Until then, verify with `pnpm lint && pnpm typecheck && pnpm build`.

## Money rules (CRITICAL)

- All monetary amounts are **integer minor units** (IDR has no sub-unit, so 1 unit = Rp 1).
- Use `app/utils/money.ts` (added in Phase 1). Never `parseFloat`, `Number("0.x")`, or `toFixed` on amounts.
- Fund balances and net worth are **derived, never persisted** to the DB.
- Domain validation in `app/domain/*` is authoritative — UI must not bypass it.

**Auto-import note:** `composables/`, `components/`, `utils/` (sometimes) are auto-imported in Nuxt 4 by default. `utils/` and `types/` typically are not — import explicitly to be safe.

## Style & lint

- ESLint extends `.nuxt/eslint.config.mjs` (generated). Local rules: `vue/max-attributes-per-line` (singleline: 3) and `vue/no-multiple-template-root: off`.
- Stylistic defaults from Nuxt config: no trailing commas, 1tbs braces.
- Tailwind v4 (`@tailwindcss/vite`-style via Nuxt) — no `tailwind.config.js`; theme via `@nuxt/ui` + `app.config.ts`.

## Database

- Dexie schema lives in `app/utils/db.ts`. Currently a demo schema (`customers`, `mails`, etc.) — Phase 2 of `/plan/TODO.md` replaces it with: `companies, security, funds, fundAllocations, transactions, assets, monthlyClosings, settings`.
- Use composite indices for hot queries (e.g. `[companyId+transactionDate]`, `[year+month]`).
- All multi-table writes must go through `db.transaction('rw', [...tables], fn)`.

## PWA

- `@vite-pwa/nuxt` with `registerType: 'autoUpdate'`.
- Icons referenced in manifest must exist at `public/pwa-192x192.png` and `public/pwa-512x512.png`.
- `navigateFallback: '/'` — all deep links fall back to dashboard when offline.

- No backend, no network calls in app code. Local-first by design.

## Common pitfalls

- **Float drift:** `0.1 + 0.2` style arithmetic anywhere in financial paths. Use integer math.
- **Persisted derived values:** never store `balance`, `netWorth`, etc. Recompute via selectors.
- **Single-row tables:** `companies`, `security`, `settings` use `'singleton'` as `id`. Enforce in `transaction('rw', …)`.
- **Delete with FK-like refs:** `funds`, `assets` cannot be hard-deleted if any transaction references them; archive instead.
- **Rollover rule:** buying an asset under target leaves the remainder in the fund (see `/docs/07-funds.md`).
- **Currency lock:** `company.currency` is not user-editable in MVP.
